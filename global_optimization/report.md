# Краткие выводы по методам

Лучшим методом в этой реализации выглядит `Nelder-Mead`.

- `Nelder-Mead` сошёлся во всех `5/5` запусках.
- Он дал очень хорошую точность: `best_f = 1.688e-09`.
- Он оказался самым дешёвым по вычислениям:
  - `avg_time = 0.0013s`
  - `avg_f_calls = 74.0`
- Он устойчив даже при далёком старте `start = [10., 15.]`, где `Adam` не сошёлся.

## Adam

- `Adam` менее устойчив: `successes = 4/5`.
- Он дал лучший единичный результат: `best_f = 4.068e-11`.
- Сильно зависит от начальной точки.
- Для старта `[10., 15.]` не сошёлся за `5000` итераций:
  - `f = 7.561e-05`
  - `f_calls = 5001`
  - `stop = max_iter`
- Из-за этого выросли средние метрики:
  - `avg_time = 0.0114s`
  - `avg_f_calls = 1120.2`
-  `Adam` иногда очень точен, но в этой задаче он менее надёжен, чем `Nelder-Mead`.

## PSO

- `PSO` сошёлся во всех `15/15` запусках.
- В `run_experiments()` задано `5` стартовых точек, и для каждой из них `PSO` запускается с тремя разными `seed`:
  - `pso_seeds = [11, 23, 37]`
- Повторные запуски нужны потому, что `PSO` является стохастическим методом:
  - начальные позиции частиц генерируются случайно
  - начальные скорости тоже задаются случайно
  - на каждой итерации используются случайные коэффициенты `r1` и `r2`
- Поэтому один запуск `PSO` не даёт полной картины; несколько `seed` нужны, чтобы оценить устойчивость метода.
- `PSO` даёт хорошие значения `f`, близкие к нулю.
- Но он самый дорогой:
  - `avg_time = 0.0034s`
  - `avg_f_calls = 2776.0`
- `PSO` в этой задаче очень устойчив, но платит за это большим числом вычислений.
